## 1. 交互与协作原则

- **中文技术沟通**：交互对话、架构方案设计、代码注释及任务总结统一使用地道清晰的中文；
- **文件优先落盘**：结构化交付物（方案设计、接口定义、数据模型）与超过 50 行源码必须直接保存至对应项目文件，严禁仅在会话中刷屏展示；
- **微片段反馈**：对话中仅返回核心摘要或高价值代码 Diff 片段（单次 ≤ 15 行），严禁在交互窗口输出未经裁剪的大段代码；
- **标准相对路径互链**：文档间互链 100% 采用标准相对路径（`./` 或 `../`），严禁包含物理盘符或本地绝对路径。

## 2. 代码质量与工程红线

- **健壮性与空安全**：
  - 查询集合无匹配数据时统一返回空集合（如 `Collections.emptyList()`、`[]`），严禁返回 `null`；
  - 单个实体查询结果为空时调用方必须显式前置防御拦截，杜绝链式空指针调用。
- **并发安全与无状态**：
  - 公共单例服务（Service、Manager）必须保持无状态设计，严禁在成员变量中持有可变业务状态；
  - 前端组件严禁直接突变外部传入的 Props，所有数据流向必须服从单向数据流。
- **异常处理规范**：
  - 严禁空的 `catch` 块；要么记录受控日志并降级，要么包装为业务语义化异常向外抛出；
  - 严禁在同一捕获块中既打印完整错误堆栈又原样向外抛出，防止日志风暴。
- **最小破坏半径**：
  - 变更严格聚焦目标需求或 Bug 修复，严禁大面积无意义重构或非相关文件代码格式重排。

## 3. Git 版本管理与操作授权

- **两级显式授权**：
  - **本地提交**：未收到用户显式指令（如“请提交变更”）前，严禁自主执行 `git commit`；
  - **远程推送**：未收到用户显式指令（如“请推送到远程分支”）前，严禁自主执行 `git push`；
- **精准暂存**：暂存必须显式指定目标文件相对路径（如 `git add src/index.ts`），严禁使用 `git add .`；
- **规范提交信息**：遵循约定式提交（Conventional Commits）规范：
  - 格式：`<type>(<scope>): <清晰中文描述>`（例如 `feat(auth): 新增多因素认证支持`）。

## 4. 安全与机密保护准则

- **零凭证明文泄露**：
  - 严禁将真实密钥、数据库连接密码、第三方 Token 或个人敏感隐私信息持久化写入磁盘；
  - 示例与模版中一律使用标准语义占位符（如 `YOUR_API_TOKEN`、`user@example.com`）；
  - 探查本地配置或系统环境变量捕获到机密时，终端展示与落盘必须强制掩码脱敏。

---

## 5. 交付物与质量门禁

- **静态代码合规**：所有新建或修改的代码必须通过项目既定 Linter / Formatter 检查；
- **自动化测试通过**：核心业务逻辑变更必须提供配套单元测试，且保证 CI 测试全量通过；
- **自闭环交付**：功能开发与 Bug 修复必须形成可验证、可追溯的闭环清单，供开发人员审查。

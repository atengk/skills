## 1. 零信任与输入净化契约

所有跨越系统边界的数据源，一律被视为**不可信输入 (Untrusted Input)**：

### 1.1 严格类型与格式白名单验证
- **接入层即时校验**：在 Controller 或 API Gateway 入口层，对所有请求参数执行严格的模式与格式验证（如使用 Zod、JSON Schema 或 Bean Validation）；
- **白名单机制优于黑名单**：校验字符集、长度限制、数值范围与枚举值，严禁采用不可穷举的黑名单过滤；
- **文件上传严格防卫**：上传文件必须重命名为随机 UUID、核验文件魔数（MIME Magic Number）而非仅信赖扩展名，并禁止在 Web 根目录下直接执行上传文件。

## 2. 零明文机密不变量与环境注入

- **零明文不变量 (Zero-Secret Invariant)**：严禁在源代码、配置文件、技术文档、单测桩数据以及 Git 提交信息中硬编码任何真实密钥或凭据；
- **环境变量与秘密管理器注入**：所有凭据（数据库密码、API Key、私钥证书）统一通过操作系统环境变量（如 `process.env.DB_PASSWORD`）或集中式密钥管理服务（Vault、KMS）动态注入；
- **配置模板使用语义占位符**：示例配置文件（如 `.env.example`）中统一使用大写语义占位符（如 `YOUR_AWS_ACCESS_KEY`、`${SERVICE_SECRET}`）；
- **会话与交互脱敏**：向用户展示的任何排错日志与交互信息中，机密字符串强制打码（如 `sk-***abcd`）。

## 3. 最小特权与访问隔离原则

- **数据库账号权限收敛**：业务服务连接数据库的账号严禁使用超级管理员（`root` / `sa`），仅授予该服务对应库的增删改查最小权限，严禁跨库越权操作；
- **微服务间令牌最小范围**：服务间 RPC 或 HTTP 调用使用限定 Scope 的短期受控 JWT 令牌，杜绝单一令牌在所有服务中全通通行；
- **文件系统权限限制**：应用程序运行时以非 root 专用低权限系统用户运行，容器环境默认启用 `readOnlyRootFilesystem`。

## 4. 审计日志与全链路防篡改

- **关键审计事件记录**：涉及敏感数据读取、权限变更、账户注销、大额交易等关键动作，必须异步记录结构化安全审计日志（包含操作人、租户 ID、IP 地址、时间戳与操作类型）；
- **日志只增防篡改**：审计日志必须存储在独立受保护的日志收集系统或具备 WORM（Write Once, Read Many）特性的存储桶中；
- **机密字段自动脱敏**：在日志拦截器层强制挂载脱敏过滤器，对敏感个人隐私数据进行脱敏遮罩后再持久化。

---

## 5. 异常安全与故障降级原则

- **异常信息防御**：对外开放 API 的响应体中严禁暴露真实的底层技术栈异常、框架内部报错、SQL 错误或服务器文件物理路径；
- **统一语义化错误码**：全局异常拦截器统一将底层异常转译为用户友好的业务错误码与抽象提示信息；
- **安全失败机制 (Fail-Safe Defaults)**：当鉴权中间件或权限校验服务发生异常宕机时，默认策略必须是**拒绝访问 (Deny)**，严禁发生鉴权旁路导致未授权穿透。

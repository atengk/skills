## 1. 核心设计哲学与黄金 5 秒法则

开发者访问代码仓库时，通常在最初 5 秒内决定是否继续深入：

- **黄金 5 秒法则**：顶部第一屏必须用一句高度概括的价值主张（Value Proposition）回答“本项目解决什么痛点、核心亮点是什么”；
- **一键可复制 (Copy-Paste Ready)**：所有快速开始（Quick Start）的命令必须确保真实可运行，零假设、零隐形依赖；
- **排版呼吸感**：严格遵循中西文盘古之白空格，标题层级清晰，杜绝未经整理的文字大段堆砌。

## 2. 标准信息架构与必选章节规范

工业级 `README.md` 必须遵循自顶向下的金字塔信息结构：

1. **项目标头与徽标区**：居中或清晰左对齐的项目名称、Slogan 与 Shields.io 状态徽标；
2. **核心特性亮点 (Features)**：使用结构化无序列表或网格卡片列出 4~6 个杀手级特性；
3. **架构与拓扑概览 (Architecture)**：提供标准 Mermaid 图表或架构全景图；
4. **快速开始 (Quick Start)**：环境前置依赖、克隆与安装、开发启动三步走指令；
5. **物理目录结构 (Directory Layout)**：清晰标注核心目录职责；
6. **配置字典与环境变量 (Configuration)**：常用核心配置项说明；
7. **生态与生态互链 (Ecosystem)**：贡献指南 `CONTRIBUTING.md`、变更日志 `CHANGELOG.md` 与许可证 License。

## 3. 状态徽标 (Badges) 规范与排布标准

徽标必须使用标准 Shields.io 矢量风格（如 `style=flat-square` 或 `style=flat`），建议包含：
- **构建状态**：CI/CD Workflow 状态（GitHub Actions 徽标）；
- **版本标识**：Release 版本号（Release Tag / npm / Maven / PyPI）；
- **质量度量**：测试覆盖率（Codecov / Coveralls）、质量门禁徽标；
- **开源合规**：License 开源许可证（如 Apache-2.0 / MIT）。

---

## 4. 代码块自解释与开箱即用准则

- **显式语言标记**：所有代码块必须标注明确的语法高亮语言（`bash`、`typescript`、`yaml`、`json` 等）；
- **跨平台命令适配**：涉及终端命令时，优先使用跨平台兼容指令或分别给出 macOS/Linux 与 Windows 适配说明；
- **敏感机密脱敏**：示例配置文件与命令中，统一使用通用占位符（如 `YOUR_API_KEY`、`localhost:8080`），严禁泄漏真实凭据。

---

## 5. 质量准入与持续同步维护红线

- **死链 0 容忍**：所有正文超链接、锚点跳转与图片链接必须有效，严禁出现 404 悬空死链；
- **零本地绝对路径泄漏**：严禁在 `README.md` 中写入任何 `file:///` 或包含本地盘符（如 `C:/`、`D:/`）的绝对路径；
- **同步更新纪律**：当新增模块、变更核心配置或升级关键依赖时，必须同步更新 README，严禁文档滞后于代码实现。

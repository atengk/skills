# Web 无障碍访问 (a11y / WCAG 2.1 AA) 审查核对单 (Accessibility Checklist)

本核对单依据 W3C WCAG 2.1 AA 级国际无障碍访问标准，提供现代前端 UI 组件与页面在可感知性、可操作性、可理解性与健壮性维度的自检清单。

---

## 1. 语义化 HTML 结构与标题层级

- [ ] **语义标签优先于 div**：页面主结构使用 `<header>`、`<main>`、`<nav>`、`<aside>`、`<footer>` 等语义地标标签；
- [ ] **严格的标题层级 (Heading Hierarchy)**：标题标签 `<h1>` 至 `<h6>` 必须保持严格逻辑嵌套，严禁为了字体大小越级跳过（例如从 `<h1>` 直接跳到 `<h3>`）；
- [ ] **原生表单控件优先**：按钮使用 `<button>` 而非带有 `onclick` 的 `<div>` 或 `<a>`；可点击元素原生支持键盘回车与空格激活。

---

## 2. 键盘全功能导航与焦点管理

- [ ] **全流程键盘可访问 (Keyboard Accessible)**：所有交互控件可通过 `Tab` 键正常聚焦，顺序符合自然阅读顺序；
- [ ] **可见的焦点指示环 (Focus Ring)**：严禁滥用 `outline: none` 或 `outline: 0`；必须提供清晰高对比度的聚焦轮廓（如 `:focus-visible { outline: 2px solid #2563eb; }`）；
- [ ] **模态弹窗焦点捕获 (Focus Trap)**：弹窗或抽屉打开时，焦点自动移入首个可交互元素，且 `Tab` 键循环锁定在弹窗内，杜绝焦点逃逸到被遮挡的底层页面；
- [ ] **Esc 键通用关闭**：所有模态窗口、下拉菜单与浮层支持通过按下键盘 `Esc` 键快捷关闭。

---

## 3. ARIA 属性与无障碍屏幕阅读器支持

- [ ] **动态展开与折叠标注**：折叠面板与下拉菜单必须标注 `aria-expanded="true/false"` 与 `aria-controls="content-id"`；
- [ ] **无文本图标按钮的无障碍标签**：纯图标按钮（如只有关闭叉号或搜索放大镜）必须提供 `aria-label="关闭窗口"` 或隐藏的文本说明；
- [ ] **动态内容广播 (Live Regions)**：表单报错、Toast 提示或异步结果区域使用 `aria-live="polite"`，便于屏幕阅读器主动向视障用户朗读最新状态；
- [ ] **图片替代文本 (Alt Text)**：所有业务信息图片必须具备明确描述的 `alt` 属性；纯装饰性图片显式声明 `alt=""` 或 `aria-hidden="true"`。

---

## 4. 视觉对比度与响应式可用性

- [ ] **文本颜色对比度 (Color Contrast)**：常规正文文本与背景对比度不低于 4.5:1；大文本（≥ 18pt 或粗体 ≥ 14pt）对比度不低于 3:1；
- [ ] **杜绝纯颜色传达状态**：表单错误、状态警告等除颜色变红外，必须伴随图标或文本提示，照顾色弱与色盲用户；
- [ ] **触摸目标尺寸**：移动端可点击元素的点击区域面积不小于 44×44px（WCAG 2.5.5 指南）；
- [ ] **动效减少偏好适配**：支持媒体查询 `@media (prefers-reduced-motion: reduce)`，为前庭障碍用户自动减缓或关闭剧烈动画。

## 1. 核心概述：好测试的标准

优质的单元测试应具备 **F.I.R.S.T.** 原则：
- **Fast (快速)**：毫秒级执行，不发起真实外网调用；
- **Independent (独立)**：用例之间零依赖，任意顺序运行结果一致；
- **Repeatable (可重复)**：无论在本地、CI 还是半夜运行，结果百分之百确定；
- **Self-Validating (自验证)**：通过布尔状态或断言自证明，无需人工肉眼查阅控制台日志；
- **Timely (及时先行)**：在生产代码编写之前完成编写。

## 2. 六大高危单测反模式

### 2.1 重言式测试 (Tautological Test)
- **特征**：断言的期望值是由被测代码相同的运算逻辑临时推算出来的。
  ```java
  // 错误示范：重言式，无论代码逻辑对错都必定通过
  assertEquals(calculator.add(a, b), a + b);
  ```
- **修正**：期望值必须来自独立的权威真理之源（硬编码常数、业务契约规定的确定输入输出）。

### 2.2 盲目通过测试 (Happy Blindness / Assertion-Free)
- **特征**：方法体内调用了被测对象，但没有任何 `assertEquals` 或 `assertThat`，仅仅为了不抛异常或刷覆盖率。
- **危害**：生产代码即便直接清空核心逻辑，测试依然绿灯。
- **修正**：每个测试必须包含至少一个针对业务返回值、状态转移或不变式的精确断言。

### 2.3 深度耦合实现细节 (Implementation-Coupled)
- **特征**：过度使用 Mockito 模拟内部私有协作者，频繁断言私有内部调用次数。
- **危害**：代码一旦进行良性重构（如合并内部循环），功能未变但测试全崩。
- **修正**：将测试挂接在公开接缝（Public Seams）上，只验证输入与输出。

### 2.4 水平切片倾倒 (Horizontal Test Dumping)
- **特征**：一口气把未来 10 个功能的所有单测全部写完，再开始写生产代码。
- **危害**：凭空臆想代码形态，测试陷入僵化，无法吸收示踪线带来的反馈。
- **修正**：严格垂直切片——一个测试 -> 最小代码变绿 -> 重构 -> 下一个测试。

### 2.5 脆弱环境依赖 (Flaky / Time-Sensitive)
- **特征**：使用 `Thread.sleep(1000)` 等待异步，或直接调用 `new Date()` / `LocalDateTime.now()` 对齐时间。
- **危害**：CI 机器负载高时随机失败。
- **修正**：注入受控时钟源（如 Java `Clock`），使用 Awaitility 或 CountDownLatch 协调并发。

### 2.6 脏状态共享 (Shared State Pollution)
- **特征**：测试之间共享可变静态变量或数据库已有数据，依赖测试运行的先后顺序。
- **修正**：每个测试用例前通过 `@BeforeEach` 彻底重置测试夹具与内存数据。

## 3. 假通过 (False Green) 深度拦截

遇到以下任何一种情况，直接判定为假通过并强制返工：
1. 断言条件为恒真式（如 `assertTrue(true)` 或 `assertNotNull(obj)` 但从不检查内部字段）；
2. 异常测试用例中捕获了异常却在 catch 块中空实现，导致未抛预期异常时仍静默通过；
3. 集合测试仅断言了 `assertNotNull(list)`，却未断言集合大小与具体内容元素。

## 4. 测试坏味道修正与自检清单

- [ ] 是否在公开接缝进行测试？（是，未调用私有方法）
- [ ] 期望值是否来自于静态契约常量？（是，杜绝被测代码自我计算）
- [ ] 是否测试了至少一个边界值与一个异常值？（是）
- [ ] 临时篡改判断条件后，测试是否会真实变红？（是，突变体被杀死）

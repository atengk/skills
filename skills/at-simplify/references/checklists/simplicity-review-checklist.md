# 代码复杂度与极简审查核对表 (Simplicity Review Checklist)

本核对表用于在代码审查（Code Review）或重构过程中，逐项审计代码是否存在过度复杂性、深度嵌套与过度工程坏味道。

---

## 1. 控制流与嵌套深度核查

- [ ] **嵌套层级 ≤ 3**：所有函数与循环体的最大缩进层级不超过 3 层；
- [ ] **无悬挂 else 块**：卫语句返回后无多余的 `else` 或 `else if` 包装；
- [ ] **循环卫语句过滤**：循环体内的过滤逻辑优先采用 `continue` 提早跳过，避免整个循环体包裹在庞大的 `if` 块中；
- [ ] **三元表达式简洁性**：严禁嵌套三元表达式（`a ? b : c ? d : e`），单一三元表达式仅用于简单的赋值场景。

---

## 2. 抽象与设计模式适度性

- [ ] **无单实现伪接口**：无为了抽象而抽象的单一实现接口或虚构多态；
- [ ] **拒绝 YAGNI 投机设计**：无未连接实际调用点的预留配置项、无用泛型参数或虚构扩展点；
- [ ] **中间层无纯透传**：无纯粹负责原样转发调用、毫无校验与转换增量的空心包装层；
- [ ] **拒绝过度拆碎**：局部使用的辅助类型与逻辑就近内聚在文件内，未引发“找代码需要跳跃 10 个文件”的碎片化异味。

---

## 3. 表达式与心智负担审计

- [ ] **长布尔表达式命名提取**：复合布尔逻辑均已提取为可读性强的具名解释性变量；
- [ ] **无双重否定陷阱**：变量与函数命名均为肯定式表达，无 `!isInvalid` 等反直觉心智消耗；
- [ ] **自解释命名消除注释**：代码本身清晰表达“做什么”，无单纯为了解释晦涩逻辑而打补丁的冗余注释；
- [ ] **单一可读返回值**：函数出口清晰，无分散在多处深层闭包内部的隐蔽隐式返回值。

---

## 4. 行为等价与单测保障

- [ ] **既有单测 100% 覆盖**：目标精简代码有充分的单元测试安全网守护；
- [ ] **全量回归无回退**：精简重构后全部测试绿灯，外部契约与返回值严格等价；
- [ ] **最小 Diff 审计**：修改严格聚焦于控制流精简，未引发无关的格式化或无关代码扰动。

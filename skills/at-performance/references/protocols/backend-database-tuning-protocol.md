## 1. 性能剖析基线与延时指标 (P95/P99)

- **告别平均值陷阱**：严禁仅以“平均响应时间 (AVG)”评估性能；核心线上 API 必须以 **P95 ≤ 200ms**、**P99 ≤ 500ms** 作为 SLA 质量红线；
- **火焰图与链路追踪 (APM)**：利用 SkyWalking、OpenTelemetry 或 Java Flight Recorder (JFR) 火焰图精确定位 CPU 密集与 I/O 阻塞热点；
- **基准测试与压测对比**：调优前后必须在受控基准环境下运行压力测试（如 k6、JMeter），记录 QPS、吞吐量与内存 GC 频率对比。

## 2. 慢 SQL 诊断与执行计划 (EXPLAIN) 分析

执行 `EXPLAIN` 分析 SQL 语句时，逐项核查以下关键列：

### 2.1 访问类型 (type 列) 治理
- **优秀区间**：`system` > `const` > `eq_ref` > `ref` > `range`；
- **严重警报**：出现 `index`（全索引扫描）或 `ALL`（全表物理扫描），必须强制优化；
- **临时表与排序警告**：`Extra` 列若出现 `Using filesort` 或 `Using temporary`，说明存在内存/磁盘临时排序，需补充复合索引。

### 2.2 深度分页优化 (Deep Pagination)
- 严禁在大表上使用 `LIMIT 100000, 20` 这种深偏移分页；
- 优化方案：
  1. **延迟关联 (Deferred Join)**：通过覆盖索引先查出主键 ID 再回表关联：`SELECT * FROM orders t JOIN (SELECT id FROM orders ORDER BY created_at LIMIT 100000, 20) a ON t.id = a.id`；
  2. **游标寻址 (Seek Method)**：基于唯一自增列或索引字段记住上一页最后一条 ID：`WHERE id > ? LIMIT 20`。

## 3. 索引设计红线与 N+1 查询根治

### 3.1 复合索引最左前缀与覆盖索引
- **最左匹配原则**：复合索引 `(tenant_id, status, created_at)`，查询条件必须包含最左侧列方能命中复合索引；
- **覆盖索引 (Covering Index)**：尽量让查询所需的所有列均包含在索引树内，实现 `Using index`，彻底避免回表（Random Disk I/O）；
- **消除索引列函数计算**：严禁在 `WHERE` 条件的索引列上包裹函数（如 `WHERE DATE(created_at) = '2026-10-12'` 会导致索引失效，应改为范围查询）。

### 3.2 根治 N+1 查询反模式
- 严禁在应用层循环体中逐条发起数据库查询或 RPC 调用；
- 统一采用持久层框架的批量查询（`WHERE id IN (...)`）、`JOIN FETCH` 或在应用层使用 Map 预先批量加载后内存组装。

## 4. 多级缓存架构与三大缓存灾难防护

### 4.1 旁路缓存模式 (Cache-Aside Pattern)
- **读取流**：查缓存 -> 命中则返回 -> 未命中查 DB -> 写入缓存并返回；
- **更新流**：先更新数据库 -> 事务提交成功后 -> **删除缓存**（严禁直接更新缓存，防范并发写覆盖）。

### 4.2 三大缓存灾难防御
1. **缓存穿透 (Cache Penetration)**：查询一个根本不存在的数据导致每次直穿 DB；
   - *对策*：空值短时间缓存（TTL ≤ 60s）或前置挂载布隆过滤器（Bloom Filter）；
2. **缓存击穿 (Cache Breakdown)**：热点 Key 突然过期瞬时大量并发打垮 DB；
   - *对策*：互斥锁（Mutex Lock / 分布式锁）回源查询，或逻辑过期永不过期；
3. **缓存雪崩 (Cache Avalanche)**：大量 Key 在同一时间集中过期；
   - *对策*：基础过期时间叠加随机扰动偏移量（如 `TTL + random(0, 300)s`）。

## 5. 线程池、连接池与异步并发调优

- **连接池容量饱和防御**：数据库连接池（如 HikariCP）大小合理计算：`connections = ((core_count * 2) + effective_spindle_count)`，避免无节制增大连接池导致数据库上下文切换耗尽；
- **I/O 密集型异步解耦**：耗时的短信发送、邮件推送、Excel 导出与统计计算，强制通过消息队列（Kafka/RabbitMQ）或异步线程池异步解耦，保证主接口百毫秒级迅速响应。

# 工作树基线核验与就绪检查单 (Baseline Verification Checklist)

本检查单用于在进入隔离工作树后、正式开始业务逻辑编写前，逐项核验工作树环境与测试基线的就绪状态。

---

## 1. 物理环境与 Git 状态自检

- [ ] **物理路径有效性**：工作树目录位于主仓库同级目录或合规隔离目录下，不存在层级嵌套冲突；
- [ ] **目标分支核验**：运行 `git branch --show-current`，确认当前处于预期的特性或修复分支；
- [ ] **初始状态纯净度**：运行 `git status`，确认工作树目录为绝对纯净状态（无未跟踪文件、无遗留冲突标记）；
- [ ] **最新提交对齐**：运行 `git log -1 --oneline`，核验当前基准提交与预期上游分支（如 `origin/main`）对齐一致。

---

## 2. 本地配置与外部依赖就绪度

- [ ] **环境配置拷贝**：必选本地配置文件（如 `.env`、`application-local.yml`）已从主工作区安全拷贝到位；
- [ ] **私密凭据占位防护**：检查拷贝后的配置文件，确保敏感配置字段采用通用占位符，未泄漏真实密钥；
- [ ] **依赖锁定完整性**：依据项目锁文件（`package-lock.json`、`poetry.lock`、`go.sum`）完成无歧义依赖安装；
- [ ] **本地服务端口冲突规避**：若需本地启动服务，已完成端口检查，避免与正在运行的主工作区服务产生端口冲突。

---

## 3. 测试基线回归绿灯核验

- [ ] **语法与静态代码分析**：执行项目 Lint / Type Check 命令，确认基线 0 严重告警；
- [ ] **单元测试全量执行**：运行全量单元测试套件，确认既有单测 100% 绿灯通过；
- [ ] **基线状态记录**：记录初始通过的用例总数与耗时，作为后续新增代码回归的比较基准；
- [ ] **故障前置阻断**：若基线测试出现既有失败，立即暂停新特性开发，报告用户评估是先修复基线还是调整基准点。

---

## 4. 完工清理与资源回收核验

- [ ] **变更全量提交**：工作树内所有成果均已形成规范原子提交，工作树保持 clean；
- [ ] **分支合并/推送确认**：分支已按用户指令完成推送到远端或合并入主干；
- [ ] **终端切回主干**：当前工作目录已安全切回主仓库根目录；
- [ ] **工作树彻底移除**：执行 `git worktree remove` 与 `git worktree prune` 彻底清理；
- [ ] **物理磁盘残留归零**：核验对应工作树物理目录已完全删除，释放磁盘资源。
